# RagChunk 生产级总体演化方案

> 目标：把当前可运行的经典向量 RAG，逐步演化为可评测、可恢复、可治理、可运营的企业私有知识库系统。

## 1. 执行规则

- 严格按版本顺序执行，不跨版本并行开发。
- 每个版本开始前确认需求、依赖、数据迁移和验收口径。
- 每个业务行为遵循 `RED → GREEN → REFACTOR`，并保留聚焦测试与回归证据。
- RAG 概率性效果同时采用标准问题集评测，不以代码测试替代答案质量验收。
- 一个版本只有在任务、测试、迁移、文档和剩余风险全部关闭后才能标记完成。
- 每个版本完成后停止实施，等待人工确认是否进入下一版本。
- 保持模块化单体；只有出现独立扩缩容或发布需求时才评估拆分服务。

## 3. V0.8：工程治理基线

### 需求

- `V08-01`：项目必须有统一 TDD 规则、工作项模板和已知基线。
- `V08-02`：测试必须区分 unit 与 integration，并提供统一执行脚本。
- `V08-03`：Pull Request 必须执行单元门禁并保存测试证据。
- `V08-04`：项目文档必须有唯一入口，区分当前文档、历史归档和生成文件。
- `V08-05`：本地 IDE、构建、上传归档和测试证据不得污染版本库。
- `V08-06`：形成版本台账；完成一个版本后必须等待下一条指令。

### 完成门禁

- 单元测试全部通过。
- 集成测试现存问题已经登记，且没有新增失败。
- TDD 规则、脚本、CI、文档索引和忽略规则齐全。
- 本版本不改变生产业务行为，因此不要求人为制造 RED；从 V0.9 第一个业务切片开始强制记录 RED。

## 4. V0.9：问答追踪与质量评测

### 需求

- `V09-01`：每次问答生成唯一 `runId`，记录成功、失败、耗时和模型调用统计。
- `V09-02`：保存检索轮次、命中片段、引用、答案、模型与 Prompt 版本快照。
- `V09-03`：提供按知识库查询问答运行列表和详情的管理 API。
- `V09-04`：支持标准问题集、标准答案、必须命中文档和应拒答标记。
- `V09-05`：批量评测 Recall@K、MRR、正确性、忠实度和引用准确率。
- `V09-06`：提供运行追踪页和评测结果对比页。

### 完成门禁

- 成功和异常请求均可追踪；记录失败不能覆盖原始业务异常。
- 相同评测配置可以重复执行并保存参数快照。
- 能比较两个模型、Prompt 或检索配置的结果。

## 5. V1.0：可靠摄取与索引版本

### 需求

- `V10-01`：以数据库任务替代进程内任务作为事实来源。
- `V10-02`：任务支持租约、幂等、超时恢复、指数退避和人工重试。
- `V10-03`：引入 `DocumentVersion` 与 `IndexVersion`。
- `V10-04`：新索引校验成功后原子激活，失败时旧索引继续服务。
- `V10-05`：提供任务列表、失败详情、重试、取消和索引回滚页面。

### 完成门禁

- 服务在解析、分块或向量化阶段重启后，任务能够恢复。
- 重复执行不会产生重复 chunk。
- 索引重建失败不影响当前在线查询。

## 6. V1.1：检索质量升级

### 需求

- `V11-01`：实现关键词/全文与向量并行召回。
- `V11-02`：实现 RRF 融合、去重和可配置候选规模。
- `V11-03`：实现文档类型、标签、时间等元数据过滤。
- `V11-04`：提供可替换 reranker，并具备超时降级。
- `V11-05`：实现章节上下文、父子分块和上下文预算控制。
- `V11-06`：提供逐阶段检索调试台。

### 完成门禁

- 标准集 Recall@K、MRR 和引用准确率相对 V0.9 基线达到约定提升。
- 编号、日期、专有名词等精确查询不弱于纯向量基线。
- reranker 不可用时系统可以降级返回融合结果。

## 7. V1.2：企业权限治理

### 需求

- `V12-01`：引入租户、用户、部门、角色和知识库成员。
- `V12-02`：所有业务表、唯一约束、缓存键和查询链路包含租户边界。
- `V12-03`：文档 ACL 在检索阶段强制执行。
- `V12-04`：记录登录、配置、文档、权限和模型调用审计日志。
- `V12-05`：提供用户、成员、文档权限和审计管理页面。

### 完成门禁

- 跨租户、越权文档、撤权后缓存等负向测试全部通过。
- 日志、导出和异常信息不泄漏未授权内容。

## 8. V1.3：数据生命周期

### 需求

- `V13-01`：定义统一 `DataSourceConnector` 契约。
- `V13-02`：先实现本地目录和 S3/MinIO，再按业务优先级增加协作平台。
- `V13-03`：支持游标、内容哈希、增量更新、断点恢复和重复事件幂等。
- `V13-04`：源端删除、权限变化和保留策略可以传播到有效索引。
- `V13-05`：提供数据源配置、同步进度和错误处理页面。

### 完成门禁

- 未变化内容不会重复解析和向量化。
- 源端删除或撤权后，相关内容在约定时限内不可检索。

## 9. V1.5：生产运维

### 需求

- `V15-01`：统一结构化日志、Trace ID、Metrics 和健康检查。
- `V15-02`：监控任务积压、失败率、检索/问答 P95/P99、Token 和成本。
- `V15-03`：实现限流、租户配额、背压、模型熔断和降级。
- `V15-04`：建立数据库、对象存储备份恢复和定期演练。
- `V15-05`：支持配置、Prompt 和模型版本的灰度发布与回滚。

### 完成门禁

- 依赖故障不会拖垮整个服务。
- 备份可以在演练环境恢复，发布过程不中断在线查询。

## 10. V2.0：规模化智能

该版本只在容量和复杂业务指标证明需要时启动，包括分布式摄取 Worker、独立搜索服务、多知识库路由、查询拆解、多跳检索、表格专用检索和高级 Agent。微服务拆分必须有明确的容量、隔离或发布依据。

## 11. 版本交付物

每个版本统一交付：

1. 版本需求与范围说明。
2. 每个业务切片的 TDD 工作项和执行证据。
3. 生产代码、数据库迁移和前端页面。
4. API 样例及兼容性说明。
5. 聚焦、单元、集成和必要 E2E 结果。
6. RAG 效果版本必须附标准集对比报告。
7. 已知限制、回滚方式和下一版本前置条件。
