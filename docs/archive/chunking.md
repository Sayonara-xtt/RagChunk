# 历史切片与检索决策

本文合并早期 `chunking`、`hybrid-chunking`、`indexing` 和 `retrieval` 文档，明确哪些设计已经进入一期，哪些只是规划。

## 1. 核心原则

- 规则切片为主：稳定、可复现、成本可控。
- AI 按需增强：规则质量不足或用户明确要求时才触发。
- AI 结果必须校验：失败时回退规则切片，不阻断入库。
- 检索与生成分离：Embedding 用于查找，Chat 模型用于切片增强和回答。
- TopK 是数量上限，Score Threshold 是质量下限。

## 2. 一期实际采用的切片基线

| 项目 | 历史默认值/行为 |
|---|---|
| Profile | `plain`、`markdown` |
| 最大长度 | 1200 字符 |
| 最小长度 | 80 字符 |
| 重叠长度 | 80 字符 |
| Markdown 边界 | 标题、空行、换行 |
| 普通文本边界 | 空行、换行、句末标点 |
| 超长处理 | 优先在句边界切分，必要时硬切 |
| 短段处理 | 与相邻段合并 |

预处理主要包含统一换行、压缩空白、归一段落，并保留 Markdown 结构标记。

## 3. 质量评估与 AI 触发

一期质量分采用简化公式：

```text
quality_score = 100
  - short_ratio * 40
  - weak_boundary_ratio * 50
  - (single_chunk_doc ? 30 : 0)
```

保留的触发规则：

| 触发 | 条件 | 结果 |
|---|---|---|
| T0 | `aiMode=always` | 强制语义重切 |
| T1 | `aiMode=never` | 仅使用规则结果 |
| T2 | 质量分低于阈值 | 语义重切 |
| T4 | 长文档仍只有一个 Chunk | 语义重切 |
| T8 | 上传时 `smartChunk=true` | 用户强制语义重切 |

一期只保留 `SEMANTIC_RESPLIT`。早期设想的 `MERGE_SUGGEST`、`QA_HOOK`、`PARENT_SUMMARY` 和 `BOUNDARY_FIX` 未作为一期正式能力。

## 4. AI 结果校验

历史方案保留的关键校验：

- JSON 必须能够解析。
- Chunk 长度必须在允许范围内。
- 去空白后的内容覆盖率不得明显低于原文。
- 不允许空段或明显重复段。
- 校验或模型调用失败时回退规则结果。

这些约束的目的不是追求最优切片，而是防止 AI 改写、遗漏或破坏原始事实。

## 5. 一期检索模型

当前早期闭环使用向量检索：

```text
问题 → Query Embedding → pgvector 相似度搜索
     → Score Threshold 过滤 → TopK 截断
     → 上下文组装 → LLM 生成
```

调参方向：

| 现象 | 调整方向 |
|---|---|
| 噪音多、答非所问 | 提高阈值或减小 TopK |
| 经常无结果 | 降低阈值、补充文档或扩大候选 |
| 型号、编号、专有名词难命中 | 增加关键词/全文召回 |
| 候选相关但排序不准 | 增加 Rerank |

## 6. 未落地规划

以下属于历史规划，后续必须重新走需求、TDD 和评测，不直接照搬：

- `structured`、`faq`、`long_manual` 等自动 Profile。
- 代码块、表格原子切片和父子分块。
- 关键词倒排、向量/全文混合召回和融合权重。
- Rerank、QA Hook、父段摘要和经济索引。
- 固定阈值或固定 TopK 作为所有知识库通用答案。

生产化方向与验收指标以 [生产级演化方案](../architecture/生产级演化方案.md) 为准。
