# TDD 已知测试基线

记录日期：2026-08-27

本文件只记录采用 TDD 工作流前已经存在的问题。它不是跳过测试的许可；新增变更不得增加基线失败，修复后应从本表删除对应条目。

| 范围 | 当前状态 | 影响 | 清理条件 |
|---|---|---|---|
| PostgreSQL 应用上下文 | Spring Boot 4 默认 Jackson 3，而 `PersistenceMapper` 仍依赖 Jackson 2 `ObjectMapper` | PostgreSQL 存储模式启动时缺少对应 Bean；数据库边界测试暂用测试专用 Bean 隔离 | 以独立 TDD 工作项完成 Jackson 2/3 迁移并删除测试补偿配置 |
| PostgreSQL/pgvector | Testcontainers 测试仅在 `RUN_PG_INTEGRATION=1` 时运行 | 默认单元回归不证明真实向量存储行为 | CI 增加稳定的 Docker 集成通道，并覆盖迁移、写入、检索和删除 |
| 本机数据库测试 | `DatabaseConnectionTest` 依赖本机数据库和 `RUN_DB_TEST=1` | 不适合作为可移植 PR 门禁 | 迁移到 Testcontainers 或独立环境验证 |
| E2E 脚本 | 仍按同步上传检查 `SUCCESS`，与当前 202 异步接口不一致 | 暂不能作为可靠完成证据 | 改为轮询文档终态，并在 CI 或受控环境稳定执行 |

基线使用规则：

- 聚焦测试和 `unit` 测试必须全绿；
- integration 或 all 出现本表之外的新失败时，本次变更不得交付；
- 不得新增 `@Disabled` 或修改 CI 条件来隐藏失败；
- 每次修复基线问题，应使用独立 TDD 工作项并保存 RED/GREEN 证据。
