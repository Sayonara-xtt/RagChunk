# 版本文档与审核规则

每个新版本从 `_template/` 复制独立目录，命名为 `Vx.x/`。历史版本可保留原格式；新版本必须使用四份标准文档。

## 生命周期

```text
需求单待审核
  → 门禁 A：开发者批准需求
  → 详细设计和测试用例待审核
  → 门禁 B：开发者批准设计与测试
  → TDD 实施
  → 回归与人工验收
  → 版本完成并停止
```

未经开发者明确批准，不得由 AI 填写审核人、审核时间或把状态改成 `已批准`。

## 版本目录

| 路径 | 用途 |
|---|---|
| `_template/` | 新版本必须复制的标准模板 |
| `V0.8-工程治理基线.md` | 新门禁建立前完成的历史治理版本 |

## 使用要求

1. 三份前置文档始终保留，L1/L2/L3 只决定详细程度；
2. 门禁 A 未通过，只能修改需求单；
3. 门禁 B 未通过，只能修改文档，不得修改测试或生产代码；
4. 实施中发生范围或关键设计变化，更新文档并重新审核；
5. 验收报告完成后停止，等待下一版本指令。

详细规则见 [版本门禁与 TDD 工作流](../tdd/TDD工作流.md)。
