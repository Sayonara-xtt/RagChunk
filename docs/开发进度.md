## 2. 核心业务流程

```text
创建知识库 → 上传文档（202 异步）→ 轮询建库进度 → 按问题检索并回答
```

| 步骤 | 用户操作 | 系统行为 |
|------|----------|----------|
| 1 | 创建知识库 | 保存 `config_json` 配置快照 |
| 2 | 上传 txt/md/docx/xlsx/xls | **202**；流式归档原件；后台异步入库 |
| 3 | 轮询文档 / 看板 | `processStage` → `SUCCESS` / `FAILED` |
| 4 | 查看切片（可选） | 校验分段正文 |
| 5 | 问答 | 按 `qa.scheme` 编排（见 [智能问答方案.md](智能问答方案.md)） |

## 4. 模块与 API

基础地址：`http://localhost:8080/api/v1`  
调试入口：`/scalar`（推荐）、`/doc.html`、`/swagger-ui/index.html`（详见 §11.3）

### 4.1 模块

| 模块 | 职责 |
|------|------|
| 知识库 | CRUD（无 update/delete）、`config_json` |
| 文档上传 | 流式归档、异步入库、看板、retrain |
| 原件存储 | `ObjectStorageService`（local） |
| 解析 / 切片 / AI | `DocumentParser`、`RuleChunker`、`HybridChunkingService` |
| 向量 / 检索 | `PgVectorStore`、`ChatRetrievalService` |
| 问答 | `ChatOrchestrator` |

### 4.2 API 清单

| 方法 | 路径 | 功能 |
|------|------|------|
| POST | `/knowledge-bases` | 创建知识库 |
| GET | `/knowledge-bases` | 列表 |
| GET | `/knowledge-bases?id={kbId}` | 单个查询 |
| POST | `/knowledge-bases/{kbId}/documents` | 上传（202） |
| GET | `/knowledge-bases/{kbId}/documents` | 文档列表 |
| GET | `.../documents/{docId}` | 详情 / 轮询 |
| POST | `.../documents/{docId}/retrain` | 重复训练（202） |

| GET | `.../upload-batches/{batchId}` | 批量任务 |

| GET | `.../documents/{docId}/chunks` | 单文档切片 |
| POST | `/knowledge-bases/{kbId}/chat` | RAG 问答 |
| GET | `/runtime` | 运行时配置状态 |

## 5. 切片与 AI 策略

```text
[后台] 解析(R0) → 规则切片(R2) → 质量评估 → [AI 重切] → 校验 → 向量化 → 入库
```

| 配置 / 参数 | 行为 |
|-------------|------|
| `aiMode=never` | 仅规则切片（T1） |
| `aiMode=always` | 全量 AI（T0） |
| `aiMode=auto` | 低质量 T2 / 单段长文 T4 |
| `smartChunk=true` | `aiMode≠never` 时强制 T8 |

质量分（简化）：`100 - short_ratio×40 - weak_boundary_ratio×50 - (单段长文 ? 30 : 0)`。

【HTTP】multipart → putStream 归档 → 202

## 10. 已知质量风险

| 问题域 | 影响 |
|--------|------|
| xlsx/docx 解析与原件不一致 | 脏数据入库 |
| 规则 / 混合切片边界 | 检索引用差 |
| AI 重切 `aiFallback` 频繁 | 切片不可预期 |
| 问答准确度 | 业务价值未验证 |
| 全链路回归不足 | 发布风险 |
